# Runtime and persistence

The HTTP Worker authenticates the administrator or verifies an HMAC capability. Effect Schema decodes each request with unknown fields rejected. A scoped Effect program loads the R2 head, creates one Rust/Wasm kernel, invokes the domain operation and releases the Wasm handle on exit. Request identity and mutable kernel instances are never process globals. The compiled Wasm module is initialized once.

## Filesystem commits

`sandboxes/<id>/head.json` contains the Rust metadata manifest, generation, sandbox policy and disposal flag. File nodes contain byte size, mode and ordered SHA-256 chunk references; directories and symlinks are metadata nodes. Rust owns canonical paths, ancestor search permissions, modes, quotas and filesystem mutations. Manifest version 4 separates directory names from inode records. Each name references one immutable inode identity; that inode owns its node payload, UID/GID and nanosecond timestamps. Multiple file or symlink names can share an inode; directories cannot. Rust rejects missing payloads, unreferenced persisted inodes and mismatched identities. Writes and metadata setters update the shared inode; quotas count its bytes once. Renaming names of the same inode is a no-op, and unlink retires the inode only after its final name disappears. Allocation never reuses an identity. New nodes initialize timestamps from the native Effect clock; mutation updates modification/change times and affected parent directories. Reads use a no-atime policy.

`sandboxes/<id>/blobs/<sha256>` contains immutable 256 KiB data blocks. The trusted Worker hashes inputs with Web Crypto and verifies block digests on reads. Access goes through the scoped native R2 binding; guests cannot address arbitrary bucket objects.

Append derives its offset from the same Rust manifest that owns the conditional publication and reuses the positional-write block plan. Unchanged prefix blocks are not downloaded or rehashed; only an existing partial tail may need reading. Metadata and content identity remain subject to the existing read-time integrity checks. A rejected append never retries against a new head implicitly.

Resize uses the same Rust block planner and Effect persistence boundary as positional writes and append. It retains full prefix blocks, reads only a boundary whose length changes and creates zero-filled growth blocks. Missing files are not created. Successful same-size resize still publishes its timestamp update. Planned content reads verify their original full-block digest before clipping a shorter retained prefix; a failure leaves the root unpublished.

A write validates its filesystem mutation, uploads all required blocks with bounded concurrency, then publishes the new head only if the original ETag still matches. The ETag operation is the visibility boundary. A failure before it leaves the previous filesystem visible. A failure after a successful head write does not undo the committed operation. A racing writer gets a conflict instead of a silent lost update. In-place snapshot restore uses this same publication boundary. Reconstruction preserves the inode allocation counter and head generation, allocates new file identities, and clears software catalog registrations. Reserved software paths can be reconstructed only during an ephemeral kernel import phase; publication is prohibited until validation closes that phase. WASI checkpoint resume compares the saved kernel generation to the current head before reentry, so an obsolete execution cannot overwrite a restored root. Read operations retain their original manifest and read its immutable blocks, yielding a consistent snapshot.

Multi-file writes execute in input order, create parent directories and report domain failures per file. Each batch is limited to 128 entries and 16 MiB total decoded content. Rust validates and applies each mutation to the request-private kernel, returning the required block hashes. The Worker deduplicates those blocks across the batch and uploads them with concurrency four before publishing the head. The block map retains at most the batch's decoded content bound. Single-file and inode writes retain their prepare, upload, then apply sequence. Successful entries and any created parent directories publish together with one final ETag check; a conflict rejects the entire publication. Infrastructure failures stop the batch before publication, while uploaded orphan blocks may remain. Empty batches do not advance the generation. Multi-file reads retain one snapshot, bound aggregate content to 16 MiB and return missing/inaccessible paths as per-file errors. Files are read sequentially with block concurrency four. Recursive listing traverses kernel metadata without per-entry R2 reads, respects depth and excluded names, follows a root alias and lists child symlinks without descending through them.

Rename modifies the metadata tree and publishes one new root; it does not rewrite file content. Shell scripts retain one private kernel. Builtin-only scripts publish its changes at completion; WASI commands can publish earlier acknowledged changes through the same session. JavaScript/TypeScript tools commit each filesystem action independently. Consequently, a failed guest can have already committed files, while a rejected shell commit leaves its private changes invisible.

Conditional shell lists gate an entire pipeline. Rust retains quote/escape provenance when recognizing a leading `!` and marks every stage of that nonempty pipeline. Effect inverts only the final stage status, retaining stdout/stderr and side effects; repeated prefixes cancel in pairs. Quoted or escaped exclamation marks and redirection targets stay ordinary words. A skipped pipeline does not resolve commands, read inputs or apply redirections; its stages preserve the last executed status for the next conditional list. Newline continuation after `&&`, `||` and `|` is distinct from a semicolon, which requires a preceding command. Rust preserves redirections in lexical order, capped at 128 per command. Effect opens them before lookup or command execution: stdout overwrite truncates immediately, append preserves an existing file, and each successfully opened output remains a filesystem effect even if a later open fails. Input opens validate read authority before the final selected input is read. The final output retains inode identity across command renames and unlink; empty stdout never overwrites the command's own file mutations. Append requires write authority rather than a guest read grant, and its internal content read uses the retained inode. Opening an existing append target without output does not publish a new head. Pipelines still pass bounded captured byte buffers between stages rather than running concurrent POSIX processes; redirected stdout is applied from the command buffer, so exact interleaving with independent writes to the same file remains open.

Snapshot export validates directory access once, computes inode and directory link counts in bounded Rust maps, and serializes metadata incrementally in one native call. Scalar stat retains the same record contract. Full bounded metadata is loaded per operation. Native workerd tests cover snapshot export with 16,384 entries, including 16,380 empty unique-inode files. That workload does not establish worst-case memory use or production latency. Public hard links and WASI `path_link` preserve shared inode identity; filesystem snapshots encode additional names as aliases to concrete entries. WASI regular-file buffers are shared by inode across their process family. Unlink and rename retarget a retained buffer to a surviving name, or detach it after the final name disappears. Descriptor stat, writes and timestamp setters use the retained inode rather than traversing its name again. Descriptor rights and the sandbox capability authorize these operations; path-based operations still check ancestor search permissions and file modes. Inode writes retain size, total-byte, digest and immutable-package checks. Detached buffers remain process state and never recreate a removed name. Paged metadata, complete descriptor/mount parity and reclaiming unreferenced blocks from live sandboxes remain open.

Manifest conversion belongs to the unconditional deployment migration `/v1/migrations/filesystem-v4`, after process receipt and output migrations. Runtime constructors accept only the current format. Conversion preserves old inode identities, timestamps, generation and package state. Retained execution checkpoint references receive converted current, published and saved-head manifests. The head write records its prior ETag in native R2 custom metadata so a retry after partial conversion can update only matching checkpoint authority. A checkpoint from another head or policy keeps its stale ETag and its conflict; migration never grants authority or renews capabilities. Metadata migration tests verify this transition and immutable checkpoint references, not execution of a historical heap across a deployment.

The scoped Rust shell owns local variables, export attributes and a prepared command. Preparation expands ordinary arguments against the pre-command map, expands prefix assignments sequentially without splitting and validates bounds before redirection effects. Redirect targets use the pre-command variables. After successful opens, null commands and special builtins commit their variable effects; ordinary commands receive temporary prefixes through the existing executable environment boundary. Pipeline stages never commit variables or cwd changes to the parent. Invalid special-builtin identifiers terminate only the current non-pipeline shell. This interpreter state is not sandbox configuration and is not persisted between execution receipts. Queued shell source still starts from its captured environment after Worker replacement.

The scoped Rust Shell shares its environment with the prepared command. Prefix, export, readonly and unset value mutations detach that map; only a validated non-pipeline commit replaces the parent map. Read-only preparation and successful commit avoid deep copies without changing persistence or binding contracts. Export and readonly attributes belong to the same scoped Shell handle, each with its own bounded set. Readonly checks reject command prefixes before file opens and special-builtin assignments/unsets before mutating a protected value.

## Background process lifetime

`processes/<sandbox>/<id>.json` owns the single process receipt and, while queued, its original verified capability. Public JSON and listing metadata omit those private grants and the internal deadline. Preparation validates its existing action, archives an immutable program, and conditionally reserves the unique ID. Synchronous calls reserve `running`; detached calls reserve `queued` before sending a Queue reference. Source loading and program entry use independent Effect scopes, releasing the preparation kernel before execution. This adds one head read to synchronous execution compared with the former combined scope.

Inline reservations persist an execution deadline before program entry: at most 15 minutes from reservation, or the shorter timeout requested by RPC. The execution owner enforces the remaining absolute budget and clears the deadline on terminal settlement. The checkpoint eligibility decision belongs to the transport lifetime; giving inline work a recovery deadline does not enable WASI handover or retain request-scoped callbacks. After an unobserved interruption, the existing repair and Queue owners settle an expired inline receipt without restoring its program or replaying guest effects. A previously requested cancellation settles as cancelled; another expired running receipt settles as failed, preserving acknowledged output. The five-minute repair cadence and native Queue delivery apply, so settlement is not immediate.

The native Queue contains only key/ETag references. Its same-Worker consumer conditionally changes `queued` to `running` before entering the guest, removes the stored grants, and stamps the native clock/deadline. Delivery duplicates, including concurrent claims, cannot enter the guest again. Archived program bytes are verified against their SHA-256 before use. Current sandbox policy and the original capability expiry remain authoritative; Queue delivery does not mint or renew authorization.

The consumer has a 14-minute wall-time budget with the independent 30-second CPU ceiling and native fuel/memory bounds. Its concurrency is one to bound active heaps. Completion publishes a real result or runtime failure under the claim ETag. A competing write is reported rather than overwritten. Guest resources close before terminal publication. A lost claim is not replayed: redelivery waits until the native 15-minute deadline, then conditionally records failure with no observed exit code. Confirmed guest side effects remain committed.

A current queued delivery checks the sandbox lifetime before restoring program or heap artifacts. A disposed or missing root settles that queued receipt as cancelled under its current ETag, clearing the private authority, deadline and checkpoint while retaining acknowledged output. A live sandbox keeps the existing retry behavior for program/runtime version mismatch. Terminal lease settlement also clears checkpoint references. A losing terminal conditional write requests native Queue redelivery instead of treating an unconfirmed write as settlement; subsequent delivery inspects persisted state. Duplicate deliveries of an already terminal receipt do not rewrite it.

The five-minute native cron and administrator maintenance endpoint share one repair owner. It lists bounded R2 pages and validates native listing metadata. Terminal receipts are skipped; queued receipts are sent directly using the listed key and ETag, without downloading their body. Running or cancelling receipts are read with concurrency four to inspect deadlines. References are sent in batches of at most 100. The consumer still loads and validates the current receipt and its authority before claiming entry; stale queued ETags cannot enter a program twice. It repairs queued work after an interrupted send or lost notification and drives expired claim observation. A Queue failure after reservation can return an HTTP error while leaving a valid queued receipt; inspect the chosen ID instead of submitting a new one. Maintenance does not grant authority to the job. [Native repair request-count evidence](evidence/process-repair-metadata-local.json) records the reduction in receipt downloads and its measurement limits. [Production Queue evidence](evidence/process-repair-metadata-production.json) records administrator repair while a real native consumer is blocked on stdin, followed by one confirmed append and collection.

`process.wait` observes the same receipt using the native clock and exponentially spaced sleeps capped at one second. Each observation has its own scope and immediately releases its kernel, preventing manifest accumulation. It rechecks disposal and expiry. Caller timeout is an observation failure; only an actual guest exit returns retained output. The remaining process and terminal requirements are tracked in `docs/parity.md`.

Deployment unconditionally migrates the old `sandboxes/<id>/runs` receipts after their Wasm source migration. It fences the old receipt under its ETag, copies its preserved public fields to the current namespace with null private authority/deadline, verifies a preexisting target before resuming a partial copy, and deletes the old key. A mismatched ID or conflicting target aborts. Runtime uses only the current stored shape and namespace. Historical completed receipts do not reenter execution. The final `process-deadlines-v1` migration visits at most 50 receipts per native R2 page, reads only running/cancelling bodies, checks their identity and listing metadata, and conditionally fills a missing deadline with the original start plus 15 minutes. Existing deadlines, queued jobs, terminal receipts, output and checkpoint references remain unchanged. It runs unconditionally with the stack after the earlier shape migrations; repeated or resumed pages do not rewrite repaired receipts.

The source WASI runtime owns PTY master/slave descriptors through the same process-local open descriptions and pipe pool. Each pair has two 64 KiB directions, with at most 64 pipe buffers per process family. The terminal owns shared raw/canonical mode, a bounded 4,096-byte unfinished line and up to 4,096 committed line or EOF records. A canonical read consumes at most one committed line; Ctrl-D on an empty line produces one zero-byte read and does not close later input. DEL edits pending bytes and echoes the edit; CR commits a newline. Raw mode preserves bytes and suppresses echo. Switching modes preserves buffered input. Slave stdout/stderr aliases share one output direction, retaining their observed write order; cooked output expands newline to CRLF. These bytes enter ordinary process capture only if the parent reads and emits them. Descriptor duplication and child stdio share terminal state and endpoint lifetime; the last alias closes its direction. Master reads drain buffered output before reporting EIO after slave closure. Native poll treats an EOF record as readable even with zero bytes. PTYs have no cross-job registry or separate persistence owner. Queued PTY stdio and host_tty.read use these same endpoints, as described below. Terminal-specific listing and metadata, resize, complete termios/foreground-signal behavior and arbitrary-crash recovery remain open. Same-build cooperative PTY handover is covered below.

## Cancellation observation

Cancellation owns the existing process receipt, not a second state document. Its conditional transition cancels queued work before entry or requests cancellation of active work. The runner races execution against a one-second native R2 metadata observation loop. An observed request interrupts the execution fiber, joins its resource scopes, and only then publishes terminal cancellation without an exit code. Successful native completion can win the race and publish its actual result. Terminal publication validates the original identity/source/start timestamp and may retry one known ETag conflict caused by the cancellation transition; it never reruns guest code or retries an uncertain write.

The runner also observes the sandbox root in that loop and once after execution returns, before settlement. The root uses a conditional R2 get against the ETag already read during admission or its latest observed ETag: an unchanged root returns metadata without manifest bytes; a changed root is decoded with `Head` before accepting its new ETag. A confirmed tombstone or missing root interrupts the guest and settles its retained receipt as cancelled. The loop adds one conditional root request per observation and one completion check, without adding a root request to each output capture. Synchronous preparation passes its root ETag directly to the supervisor; queued delivery passes its successful preflight ETag. The first observation therefore does not unconditionally download an unchanged root again. Changed roots still require validation, including a tombstone published after admission. This reduces transferred manifest bytes and decoding work without removing a lifetime check or lowering the R2 request count. This is cooperative disposal observation, not instantaneous preemption or an atomic transaction between root disposal and process settlement. Already issued external effects retain their own lifetime.

The API requires `execute` and returns only the native summary, so it cannot reveal captured output without `read`. Full guest responses encode `RunRecord` before its summary variant to preserve process wait output. Queued grants clear on cancellation. The delivery/repair owner also observes `cancelling` leases; after the native consumer lifetime it records stopped cancellation without resuming guest state. Synchronous native calls cannot be preempted midway, and previously issued remote effects do not roll back.

Metadata-only process operations use the shared head acquisition owner without creating a filesystem kernel. Actual execution and filesystem operations acquire the kernel through `open`. This avoids rebuilding and retaining manifest heaps merely to inspect authorization/disposal during polling.

## Retained output replay

The run receipt owns stdout/stderr references to immutable 64 KiB R2 blocks. `process.output.read` fetches only the blocks needed for the requested range, verifies their size and SHA-256, and emits base64 events with at most 4096 bytes each. Caller byte/event limits bound delivery. An absolute byte cursor spans stdout then stderr; each event also identifies its offset within the stream. This presentation is stable across completed-receipt reads; original interleaving between streams remains open.

WASI transfers native byte arrays across its Wasm ABI. Capture and settlement archive those bytes without a UTF-8 round trip, including null bytes and invalid UTF-8. `RunRecord.output.stdout` and `stderr` remain text views; consumers requiring exact bytes use output pages. Older receipts retain the bytes they originally stored; data lost before capture cannot be reconstructed. The existing receipt/block format remains unchanged.

Authorization and sandbox existence/disposal are checked through the same inspection owner. Unknown executions, invalid byte cursors and unsupported inputs fail explicitly. Active receipts without captured output report pending availability; failed/cancelled receipts with no retained output report unobserved availability. Prefix validation uses stored block hashes, including the previous partial block, without rereading old blocks. Rewound or changed prefixes fail publication. Snapshots persist at guest yields and at observed WASI completion before settlement.

## Live output checkpoints

The native runtimes expose captured stdout/stderr through their generated Wasm ABI. QuickJS retains the lexical capture function as a Rust-owned persistent handle and removes its temporary global; Python reads its native StringIO captures while suspended; Wasmi returns native byte buffers. A native byte-count check avoids copying unchanged WASI buffers. The host validates and publishes only changed monotonic prefixes. Shell output capture composes byte buffers of previous terminal output with the current command, suppressing stdout sent into a pipe or redirected file and preserving stderr routing.

The process completion owner supplies the capture callback and tracks only its last acknowledged snapshot and ETag. The callback updates the same running receipt, preserves the private deadline, and uses a conditional write. Cancellation remains an independent metadata transition; a losing capture detects it and stops rather than overwriting it. Snapshot ETags become the expected terminal publication version. Partial snapshots have null result/exitCode; they survive cancellation, runtime failure and expiry of an interrupted consumer observation. Terminal success replaces them with the real completed output.

`process.output.readLive` uses independent stdout/stderr offsets, preserving cursor validity when streams grow separately. Its events contain captured bytes and stream-relative offsets, not an invented interleaving sequence. The original combined numeric cursor stays terminal-only while a partial output exists. Both operations preserve their authorization and byte/event limits. A snapshot with no new bytes can still belong to an active process; state, not an empty page, determines completion.

Wasm snapshots are captured at native host yields, and shell snapshots at command boundaries. Synchronous printing has no external persistence until those boundaries. Abrupt interruption can lose bytes from an unacknowledged step. Snapshot publication retains the existing receipt and immutable blocks. Identical blocks upload once per publication, and already confirmed blocks are reused. Raw WASI streams are supported through byte pages; original stream order and complete POSIX option/locale semantics remain open.

## Guest boundary

One ordinary Worker loads precompiled Rust/Wasm modules for its filesystem kernel, QuickJS, Oxc and WASI/Wasmi. JavaScript runs in a fresh QuickJS runtime with its own heap, stack ceiling, interrupt budget and microtask ceiling. TypeScript is transpiled by Oxc before entering that runtime. Each module compilation owns a fresh Wasm instance with 64 MiB maximum linear memory; generated native bindings are instantiated through a build-time factory. This contains compiler stack/memory traps instead of retaining a poisoned instance across requests. Guest Wasm is validated eagerly and translated by Wasmi on first use, with fuel and memory limits; it is never dynamically compiled using the platform WebAssembly API. Validation and translation remain outside instruction fuel, matching the previous eager engine; module-byte admission and the platform CPU limit bound this work. Instructions and memory operations retain their fuel costs. CPU slices use Effect’s cooperative yield instead of a fixed one-millisecond sleep. Tests reject invalid unused function bodies before entry and verify continuation, signals and cancellation with the same runtime.

Rust exposes a step/respond protocol for asynchronous capability calls. Effect validates each requested action and executes it using the original trusted sandbox identity, expiration and permission set. Guest JavaScript receives only JSON responses and no host JavaScript references. Capability functions resolve guest promises through native QuickJS handles; dropping an execution releases its pending handles and runtime. No native platform imports, Worker environment, R2 binding or direct network function exist inside QuickJS.

Rust Oxc discovers static imports and reexports and rewrites dynamic imports to the native asynchronous promise bridge. The Worker resolves canonical paths through the Rust kernel and reads immutable blobs from one filesystem snapshot, respecting read permissions and following symlinks. Each first dynamic import acquires the current authorized snapshot, so files created during guest execution can be imported. Preloaded graphs preserve native ESM cycles and module identity. Inline script/evaluation and file entry points use the same graph owner. Graphs are limited to 128 modules, 128 imports per module, 1 MiB per module source and 8 MiB serialized data. Computed and literal dynamic imports resolve with native QuickJS module namespaces, including function exports and cached identity. Concurrent requests for the same module share that cache. Package/Node resolution, import attributes/URL query identities and execution options remain pending. Preflight failures do not reserve execution IDs. Initial source digests identify the preflight graph. When execution terminates, including controlled CPU/memory failures, imported source snapshots are archived and the terminal receipt points to the complete captured graph. A platform crash before that commit can still leave the initial running receipt.

`interruptBudget` measures interrupt callbacks, not CPU milliseconds. Wasmi uses 1,000 fuel units per budget unit. Memory limits are per guest; the Cloudflare Worker also retains its native aggregate CPU/memory limits. QuickJS has a 512 KiB stack ceiling, 10,000 microtasks and 256 capability requests. Serialized output is bounded. Python also uses 1,000 native Wasm meter charges per budget unit. Trusted interpreter bootstrap has a separate fixed charge ceiling. Its memory ceiling allows the configured guest bytes beyond the static module memory, with 64 KiB granularity.

The tool contract excludes administration, process creation and lifecycle mutation. Network calls require both the `network` grant and an exact sandbox policy hostname. HTTPS GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS accept explicit request headers and an optional UTF-8 or canonical-base64 body bounded to 1 MiB. GET and HEAD reject bodies. Transport-managed headers cannot override routing or message framing; application authorization headers are explicit guest input, never inherited from the host request. Headers are bounded to 128 entries and 64 KiB, with an 8 KiB value limit. Responses preserve status and headers; bodies retain the sandbox output byte limit. URL credentials, nonstandard ports and IP destinations are rejected. Redirects are returned without following them. Network bodies and request/guest responses are read through bounded native Effect streams.

Wasm accepts `_start() -> ()` for [WASI Preview 1](https://github.com/WebAssembly/WASI/blob/a2b96e81c0586125cc4dc79a5be0b78d9a059925/legacy/preview1/docs.md) commands or `run() -> i32` for standalone guests. Each execution owns a fresh Rust Wasmi host instance and its native Wasm memory; freeing the guest releases file buffers and makes the host instance collectible. Native generated bindings are scoped by a build-time factory, retaining their original types. Wasmi interprets the submitted module inside this precompiled instance, with fuel, linear-memory, table and instance limits. The platform never compiles submitted guest bytes.

Implemented Preview 1 operations cover preopen discovery, descriptor rights, file open/create/truncate, vectored read/write, positional read/write, seek/tell, close, sync/datasync, captured stdout/stderr, process exit, clock resolution/time and cryptographic entropy. Argument/environment syscalls expose the supplied UTF-8 strings with native pointer arrays and NUL terminators. Stdin reads preserve a cursor and return EOF after its byte stream is consumed. No Worker environment variables are inherited. Unknown process options are rejected. Unsupported registered syscalls return `NOTSUP`; unsupported imports or signatures fail instantiation. File/path stat, directory enumeration, mkdir, rename, unlink/rmdir and symlink/readlink are implemented. Directory cookies index a captured sorted snapshot, and truncated buffers preserve the native dirent layout with persisted inode identities. Append/nonblocking flags are retained on descriptors; buffered regular file/directory I/O completes immediately. The [Preview 1 setter contracts](https://github.com/WebAssembly/WASI/blob/a2b96e81c0586125cc4dc79a5be0b78d9a059925/legacy/preview1/docs.md#fd_filestat_set_times) cover descriptor resizing and descriptor/path access and modification timestamps. Resizing preserves the cursor, zero-fills growth and restores the prior buffer on an errno response. Each syscall checks its own descriptor right and the sandbox write grant. Timestamp values cross the host boundary as decimal strings and enter native `u64` values without JavaScript numeric rounding. Explicit and NOW flags update only selected fields; NOW uses the request's trusted Effect clock and a zero flag mask leaves all times unchanged. Symlink lookup flags retain directory confinement. The same operations apply to detached open descriptions without recreating directory entries. Additional sync flags, hard links, sockets and software-specific extensions remain open.

WASI owns one private filesystem snapshot, reusing the process's acquired Rust kernel. File mutations validate permissions and quotas and upload immutable R2 blocks before reporting successful writes. Their metadata publishes together when execution finishes; an explicit sync publishes a checkpoint and advances the session ETag. An unsynced trap leaves private changes invisible, while already published checkpoints survive later traps. A conflict stops execution and preserves the competing root. Reads share cached file bytes between descriptors without repeated R2 downloads. A separate cache identity owns open file descriptions; replacing or unlinking their directory entry detaches the old cache, and later writes update only that live description. Rename moves linked cache paths and open directory bases. Detached files retain their real inode and metadata, report zero links, and disappear when the last descriptor closes. The cached bytes are in the trusted interpreter, outside the guest's linear memory. Preparing a write-only file uses kernel write permission; guest reads still require both its descriptor read right and the capability's read grant. Directory descriptors reject lexical and symlink escapes. Capabilities are checked before host operations and final publication.

The native `host_process.proc_spawn_v4` ABI accepts PATH separately from argv/environment. A null PATH pointer means an exact executable path; a present empty PATH means the child's current directory. PATH entries are resolved after ordered file actions, and an executable containing a slash bypasses PATH. Search skips missing entries and non-directory components, remembers access failures, and returns EACCES if no executable is found after a denied candidate. Every successful spawn DUP2 action clears the child descriptor's CLOEXEC flag, including a source equal to its target; the parent retains its original flag and shared file offset. Direct fd_dup2 with equal descriptors preserves its flags. The SIGDEFAULT mask resets selected inherited ignored dispositions. Scheduler attributes accept SCHED_OTHER with priority zero; nonzero priority returns EINVAL and other requested policies return EPERM. RESETIDS has no identity transition because virtual real and effective IDs are already zero; USEVFORK is an optimization hint and does not alter process isolation.

Native `proc_exec` and `proc_fexec` prepare a Wasmi image before replacing the current guest. Success retains PID, parent/group/session membership, existing children, cwd, stdio, shared file offsets, ignored and pending signals, and the signal mask. Caught handlers reset. Only successful replacement closes native CLOEXEC descriptors and the caller's explicit close list. Invalid images and missing/denied executables return errno without closing descriptors or discarding the old frame. Descriptor execution reads the complete buffered image without moving its offset. Replacement preparation counts temporary memory against the family ceiling and shares the original fuel/host-request budget. Every replacement releases the previous Store. When children remain active, each guest turn yields through native Effect scheduling after releasing the family semaphore. This lets a newly forked child run while a parent repeatedly queries the clock; the same shared instruction, memory and host-request limits still apply. Fuel slices batch interpreted CPU work between bridge returns, reducing parent polling and Effect scheduling overhead without increasing the process family's total fuel. The [local quantum measurements](evidence/wasi-quantum-local.json) retain raw samples and distinguish throughput from interruption latency.

The native WASI descriptor table owns regular-file aliases at `/dev/fd/N`. An alias opens the existing inode with an independent offset and a subset of its descriptor rights; it does not read the original pathname, create an R2 copy or consume another file buffer. Alias opens reject writes, creation, inheritance and unsupported flags. Only regular-file reads and followed metadata are supported; this is not a mounted devfs or support for descriptor directories and pipes.

Descriptor exec captures bytes from its validated executable descriptor and passes them through the shared bounded interpreter loader. The first script argument identifies the inherited descriptor alias, so its interpreter retains access after rename or unlink. A script descriptor in the explicit close list or marked close-on-exec fails with ENOENT before process replacement. Failure preserves the old frame, offsets and descriptor flags. Successful replacement retains the existing native PID, descriptor, signal and resource lifetime. Descriptor numbers remain local to each guest process.

Wasm start sections are exported internally with native wasmparser/wasm-encoder and removed from synchronous instantiation. The start function runs through the same resumable invocation path after image commit, before its command entry point. Filesystem suspension, signals and fuel slices therefore keep the current process state and grants; an initializer trap fails the committed image and cannot return to the old exec caller. The worker does not compile guest code through the platform WebAssembly API. Cross-language exec and shebang command selection remain open.

WASI limits include 128 directory/file descriptors including the root preopen, three stdio descriptors, 16 MiB aggregate cached file bytes, 128 iovecs and 256 host requests. Closing a file's last descriptor releases its cache allocation. Buffer exhaustion, invalid pointers, quotas and narrowed descriptor rights return native errno values. Host request-budget exhaustion traps instead of permitting an unconfirmed buffered mutation to continue. Denied memory/table growth returns the native Wasm failure value instead of a forced debug trap; the configured quotas stay enforced, and a guest may continue with a smaller allocation. Reads currently load complete files, and each write rehashes its current contents. Ranged block access and large/mixed/concurrent production workloads remain performance gates.

The shell is a trusted bounded interpreter, not arbitrary native process execution. Rust owns parsing and text commands, while Effect orchestrates filesystem calls and commits. It is not a complete POSIX shell. Durable access uses the scoped capability API; Node filesystem compatibility and synchronous Python filesystem imports remain pending.

A scoped Rust `Shell` handle owns the parsed word fragments and captured environment. Its bridge plan exposes control flow and redirection kinds; words remain inside Rust. Effect releases the handle on success, failure and interruption. Arguments expand after conditional gates, and each redirection word expands immediately before its lexical open. Named environment parameters and previous pipeline status support unquoted and double-quoted expansion; single quotes and escapes preserve literals. Unquoted values split on space, tab and newline, while quoted empty values retain an argument. Expansion results never re-enter the parser. All commands in a pipeline read the status from before that pipeline; subsequent commands see its final, possibly negated status.

Expansion has an 8192-token/fragment parser bound, 4096 resulting fields and a 1 MiB expanded-byte budget per argument vector or redirect word. An ambiguous redirect fails after preserving prior opens, including an already selected stderr target. Argument expansion fails before opening that command’s redirects. Unsupported pathname patterns, parameter operators, positional parameters and command substitution fail explicitly. Shell-owned PWD/other variable initialization, configurable field separators and the remaining POSIX expansion stages are not implemented. The archived shell source/environment contract is unchanged; queued jobs expand their captured map after Worker replacement.

## Interactive stdin

`StoredRun.stdinMode` is the durable declaration of `closed`, `pipe` or `pty` input. Queued WASI execution accepts pipe and PTY modes; other runtimes reject interactive input before reserving a receipt. PTY mode attaches a shared native slave to descriptors 0, 1 and 2, with a retained input writer and output reader owned by the process family. Its R2 head at `process-input/<sandbox>/<id>.json` owns accepted byte size, ordered immutable `sandboxes/<id>/stdin/<sha256>` blocks and EOF. Execution receipts and output publication never rewrite this head. Conditional ETags serialize append/close; expected byte offsets make exact write retries idempotent. Failed publication can leave an unreferenced immutable block. Initialization is recoverable from the archived initial stdin when a reservation exists but its head write was interrupted.

A scoped feeder validates addressed block sizes and SHA-256 before delivering at most 64 KiB into the Rust family's existing native pipe. The same pipe endpoints survive spawn and exec. Native reader/writer lifetimes, poll readiness, nonblocking behavior, EINTR and signal restart remain owned by that pipe implementation. A closed input head closes the writer only after all accepted bytes have been fed. Losing the last native reader closes the R2 head. Cancellation closes the feeder scope, and settlement seals the input head. Status uses the same derived closure as append/close: an explicit input EOF or a receipt outside queued/running closes input, including a cancelled parked execution whose separate input head was not rewritten. Status reads do not repair or mutate the input head. Input acknowledgement reports retention rather than guest consumption. Queued input survives Worker replacement; live interpreter resumption remains a separate gate.

PTY input uses the same immutable blocks and expected-offset protocol. Native delivery advances the consumed offset only by the bytes accepted by the terminal, retaining any remaining block bytes for later delivery. Echo is captured while the guest is still waiting for a complete line. Transport EOF flushes an unfinished canonical line before closing the writer; Ctrl-D remains a transient terminal EOF rather than closing the durable input head. Both slave output streams drain into the existing stdout capture in observed write order, preserving raw bytes in output blocks. That capture still enforces the existing output budget; an over-budget echo fails the process while retaining previously acknowledged output. A shared native attachment survives spawn and exec. Input and output survive replacement before guest entry and after completion through the existing R2 owners. A confirmed same-build cooperative heap checkpoint also retains the unfinished canonical line, raw mode, unread bytes, descriptor aliases and native family handles. Native replacement tests resume a pending host_tty.read, a raw-mode clock poll with buffered input and a parent/child family. They append input and EOF after parking, then verify exact byte replay and unchanged terminal receipts after stale Queue delivery. A cancelled parked receipt never reenters its guest and retains its acknowledged output. These tests use the existing 30-second lease and native request-local Effect TestClock; they do not prove recovery before a checkpoint, cross-build heap migration or a published interactive shell resuming after replacement.

The PTY feeder uses an Effect exponential schedule starting at 16 ms and capped at one second, reset after actual input progress. It backs off during inactivity and waits for existing process-family notifications as well. Ordinary pipe input retains its one-second interval. This changes the local interactive latency/request tradeoff; it is not a measured production cost advantage.

The unconditional output migration converts v2 inline and v3 chunked receipts to v5 with closed stdin and no continuation. It preserves grants, deadlines, output references and public summaries. Runtime reads only v5 receipts; legacy shapes are confined to the migration owner. The migration returns a continuation cursor after at most 50 listed receipts. Alchemy follows each confirmed cursor and logs page receipts, keeping individual requests below the client timeout. Retrying from the beginning reads persisted metadata and skips already converted receipts.

## Rust heap checkpoints

The internal Wasmi checkpoint path parks native guest ownership in a bounded Rust registry and persists the quiescent host Wasm memory as immutable 64 KiB R2 pages plus a content-addressed manifest. The manifest records the exact compiled Rust runtime digest and PID/handle mapping. Restoring validates the manifest, layout, runtime digest and every addressed page before adopting any guest. A different Rust build is rejected; the loader never compiles uploaded guest code through the platform WebAssembly API. Repeated page hashes upload once within a snapshot. Restoration groups page offsets by their native hash, fetches and validates each distinct 64 KiB payload once, then copies it to every addressed slot. At most four payload reads are active; only the bounded offset groups outlive a payload, with no cross-request cache. Native tests count real R2 gets and corrupt a payload shared by multiple slots.

Replacement-workerd tests restore an out-of-fuel continuation without repeating entry or resetting fuel, a caught signal handler with its mask/frame, and a parent/child pair with shared pipe buffers, EOF and child wait status. Corrupt pages and incompatible runtime manifests fail before native resume. These helpers are internal and the fixture Worker is separate from the deployed application.

Queued WASI execution hands over after 50 million shared fuel units or 30 seconds blocked in a root poll, signal stop or child wait. It freezes all live native guests under the family semaphore, captures the private kernel manifest and acknowledged filesystem base, and persists a heap/context reference. Receipt v5 then conditionally transitions to queued with the original grant, deadline, output references and checkpoint count. Queue notifications and cron repair can deliver that confirmed state. The next conditional claim clears the checkpoint reference and grant before resuming native instructions. Duplicate deliveries cannot claim it twice.

Restoration rebuilds the kernel snapshot, live child scopes, shared stdin feeder and virtual monotonic clock continuity. Root stop and child waits wake at most one second apart to check the handover deadline. Replacement-worker tests retain both parent and child, inherited stdin/stdout, wait status and a stopped parent resumed by the child through SIGCONT. A failed restore, expired grant or cancellation retains acknowledged output. Unsynchronized kernel/file-buffer state survives a confirmed handover while remaining invisible to other callers until publication. The original process deadline and total fuel are preserved across claims. `process.recovery.status` exposes the confirmed count and whether a queued checkpoint is resumable.

An unexpected loss while a claim is running still settles at its deadline without replaying guest entry or external mutations. Checkpoints are consumed on claim rather than reused after an unobserved operation. Complete arbitrary-crash recovery still requires a transaction/intent boundary for effects outside the interpreter.

## Execution receipts

`sandboxes/<id>/code/<sha256>` stores JSON programs. A Wasm program captures source bytes as canonical base64, full argv, the supplied environment and stdin. Its digest identifies the complete input, not just the binary. File execution snapshots the binary before creating its receipt; later file edits do not change that artifact. `processes/<sandbox>/<id>.json` stores a unique execution ID, language, source digest, timestamps, lifecycle status and output block references. The initial receipt is conditionally created. A duplicate ID is rejected before execution. Completion conditionally replaces only the original running receipt. Run summaries are encoded into native R2 custom metadata at the same write, so paginated listings fetch only the requested metadata page and do not download each execution output. Cursors and limits pass directly to the owning native API.

A failed transport does not authorize repeating the same execution or deleting its receipt. An interrupted host can leave a `running` receipt even if the guest has stopped. Queued executions use native Queue delivery with conditional claims; deadline recovery records failed or cancelled observation without replay. Cancellation is cooperative at native yield boundaries, rather than POSIX signal handling. Results and filesystem writes are not one cross-object transaction.

Disposal conditionally publishes the existing head with its deletion marker. A confirmed marker makes subsequent disposals succeed without rewriting the object. A losing compare-and-swap rereads the head: another confirmed disposal succeeds, while an intervening live mutation reports a conflict. Authority is checked before this read, including for already disposed sandboxes. The retained tombstone blocks ID reuse. Disposal invalidates future reads/writes/tool calls. It does not reclaim data or instantly terminate already-running guest CPU. Policy changes use the same root commit, require management permission and preserve files. Execution-budget changes apply to subsequently created guest runtimes; subsequent tool calls read the current network policy.

`vm.reclaim` requires an unexpired management capability and a confirmed disposal marker. It handles one bounded batch per call, with `limit` between 1 and 1,000. `reclamations/<id>.json` owns the current phase and a fresh publication revision; conditional writes prevent stale progress from overwriting a later phase or sweep. Process receipts are removed first, followed by input records, schedules and the sandbox object prefix. Nonterminal process metadata blocks the batch, and later phases check for reappearing receipts before deleting data. Only process listings request custom metadata. The [native R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/) permits up to 1,000 deletion targets and may return fewer listing entries when metadata is included. Each pass starts from the first remaining native R2 page, so deletion and a lost response do not require retaining a cursor into a changing prefix. The head is excluded from batch deletion. At completion, a fresh native Rust kernel supplies an empty manifest and the disposed head environment is cleared; the tombstone and small progress record remain.

The response reports `pending`, `blocked` with process IDs, or `complete` for the observed sweep. `removed` counts acknowledged deletion targets for that call, not a storage-usage measurement or a cumulative count across concurrent calls. A later call after completion starts a new sweep. In-flight external operations and R2 writes are not atomically fenced with reclamation; late objects require another pass. This is explicit collection, with no automatic retention timer or background collector. Disposal retains private execution receipts and output. Reclamation removes both. The administrator may mint a fresh management-only capability for a disposed root; new read, write or execution grants remain forbidden, and the ID cannot be recreated.

## Infrastructure and production gate

Alchemy declares one ordinary sandbox Worker, its private R2 bucket, and the execution Queue with its consumer. The unconditional deployment action first converts root configuration to head version 3 in bounded pages, runs Wasm-input and process-receipt conversions and output/input migration, then converts archived program environments and checkpoint roots before converting filesystem manifests to version 4. The filesystem conversion and checkpoint authority rules are described above under the shared inode graph. Only version 4 manifests enter runtime acquisition. Conditional ETags guard publication; repeated migration is idempotent, and a concurrent head change aborts. During the cutover, old manifests reject reads until the deployment action converts them. The endpoint uses native R2 bindings because the installed Alchemy HTTP bucket client does not forward conditional PUT options. Deployment migration requests retry only HTTP 404 for a bounded interval while a newly added endpoint propagates. Other failures stop the deployment action. Runtime imports of provisioning types remain erased. Local integration tests use Alchemy's native workerd runtime, R2 and Queue bindings with its actual HTTP server.

The deployment action also runs the Wasm-input migration on every deploy. It converts old raw Wasm artifacts to the current JSON program contract with empty argv/environment/stdin, preserving historical defaults. It verifies the old source digest before conversion, writes the immutable new artifact, then conditionally rewrites each receipt and its native listing metadata. A concurrent receipt update aborts rather than overwriting it. Receipts without listing metadata are recovered from their bounded body. Modern artifacts carry the producer's `program-json-v2` metadata marker and are skipped on later runs. Old immutable objects remain retained in live sandboxes; disposed-sandbox reclamation removes their owning prefix. Runtime execution uses only the current program shape.

The filesystem migration returns a typed continuation after each bounded page. Its first phase lists sandbox prefixes with the native R2 delimiter and converts at most 25 heads, skipping orphan prefixes without a head. Its second phase scans at most 25 process receipts globally and converts retained checkpoint manifests against the current root and recorded prior ETag. The response counts changed roots and checkpoint references. Alchemy consumes both phases unconditionally until the cursor is null; no operator gate or request-time migration exists. Each request validates its cursor before storage access. Replaying a page rereads current persisted state and leaves already converted objects unchanged; a cursor is progress, not authority. A failed HTTP observation does not roll back earlier conditional writes. A later deployment starts the bounded scan again and converges from the confirmed state.

The user selected the `minutei` Alchemy profile for development and deployment. Local test results do not establish deployed behavior, remote CPU enforcement, production latency or a successful CI run; record those gates separately after executing them.

## Software packages

The Rust kernel decodes the upstream v2 `.aospkg` wire format using records generated from its pinned BARE schema. Header, embedded versions, bounded inventories, canonical paths, byte ranges, command targets, directory projections and environment values are validated before installing. Complete consumption and native re-encoded lengths reject trailing bytes, duplicate map keys and lengths that would wrap in wasm32. Package and file SHA-256 identities derive from actual bytes.

The current manifest owns the package catalog, command bindings and file ownership. Installation stages a private snapshot, validates namespace and byte quotas, uploads deduplicated immutable blocks, then conditionally publishes the filesystem and catalog together. A losing ETag publishes neither. Projection conflicts and duplicate package versions reject the staged snapshot. Raw source files can change afterwards without changing installed bytes. Live sandboxes retain immutable blocks. Explicit reclamation of a disposed sandbox removes them after its process receipts are terminal.

Package directories and their declared aliases are readonly for ordinary filesystem, shell and WASI operations, including permission/time changes and removal or relocation of an ancestor. Only the package domain mutates these projections. Removal deletes its package subtree and declared mounts; command ownership falls back to the first remaining provider. Package metadata serializes canonically so migrations do not rewrite an unchanged catalog.

`process.execFile` resolves an installed command or a sandbox path and executes WASI binaries or executable shebang scripts whose interpreter chain ends in WASI. Rust parses the first header within 256 bytes, preserves the complete optional argument as one argv item, rejects NUL/invalid UTF-8, and bounds interpretation to four scripts. Every script and interpreter requires executable mode. The shared executable loader resolves interpreter paths without PATH search, using `/home/cirro` for host `execFile` and the native process cwd for WASI path exec/spawn. It preserves a binary caller's argv unchanged and inserts interpreter argv only for a shebang. The initial host command retains PATH lookup. WASI path exec/spawn read the current interpreter at the syscall boundary; host admission captures its initial interpreter before Queue delivery. Descriptor-based fexec uses the same loader with its inherited regular-file alias. WASI path exec/spawn reject malformed images with ENOEXEC (45), including non-module text and truncated Wasm; failed admission retains the caller's descriptor state and does not accept a child PID. Resolved interpreter bytes, argv, environment and stdin enter the existing immutable program archive before Queue admission; script body files are read from the live filesystem by the interpreter. Mutating a script after admission does not change the captured interpreter or argv, but can change the body it later reads. These argument rules follow [Linux interpreter script semantics](https://man7.org/linux/man-pages/man2/execve.2.html); the header limit rejects overlong headers rather than truncating them. The existing 128-argument and 64 KiB configuration budgets include inserted script paths and optional arguments. Sandbox environment overrides first-provider package defaults and explicit caller values override both; Worker bindings are never inherited. Other command runtimes, guest working directories, default release packages, large package streaming and reclamation of unused blocks inside live sandboxes remain open.

The shell resolves external executables using the package-provided PATH or its default directories; a qualified executable path resolves against the shell's current directory. Executable mode checks distinguish missing commands (127) from inaccessible commands (126). Shell builtins retain precedence. Standard input from a pipe or redirection enters the WASI byte stream, and captured output flows into the next pipe or output file. Native WASI spawn owns the child cwd, including ordered chdir/fchdir actions; the executable loader and subsequent path exec use that same child cwd. The published Brush exec builtin sends no live libc cwd in its exec ABI: a `cd` followed directly by relative exec can still fail because libc cwd changes are not synchronized with the native process cwd. A spawned child receives its explicit cwd correctly. This synchronization remains a parity gate; environment PWD is not substituted for the missing transport.

The storage publication owner updates the request-local session's manifest and ETag only after a confirmed R2 write. WASI retains a snapshot of its entry state and each acknowledged checkpoint. On failure it restores that snapshot within the same Rust kernel, preserving earlier shell changes and synchronized guest changes without retaining unsynchronized guest mutations. Shell recovery can continue against the updated session. Publication conflicts and expired capabilities abort the shell instead of continuing with stale authorization or state. Infrastructure failures propagate; an uncertain remote write is not treated as rolled back.

`fd_allocate` checks its own descriptor right, preserves the cursor and existing bytes, and zero-fills growth through the same upload/publication path as resizing. Offset/length overflow, file quotas and aggregate cache limits return native errno; denied writes restore the prior buffer.

`poll_oneoff` bounds subscriptions to 128, validates the native 48-byte subscription and 32-byte event buffers and echoes full 64-bit userdata. Regular file, bounded stdin/stdout and descriptor errors complete immediately. Narrowed rights and closed descriptors produce per-event errors; fixed stdin reports its exhausted stream as hangup, while regular-file EOF remains ready without a peer-hangup flag. Realtime/monotonic relative and absolute clocks use the native Effect clock and scheduler. The earliest deadline wakes the call, the clock is rechecked after scheduler wakeup, and precision permits additional coalescing that this implementation deliberately does not request. CPU clocks remain explicit per-event `NOTSUP`. Capability expiry bounds a long wait and aborts execution before later guest operations.

Python runs through `src/python.ts` in a fresh RustPython Wasm instance for every run. `crates/python` freezes only the encoding bootstrap and the tool awaitable; the Python standard library package is a build dependency. Native compilation supports top-level await and final-expression results. Coroutine yields cross the existing Effect Schema tool boundary; R2 operations keep their sandbox grants and acknowledged mutations survive later guest failure. Each run permits 256 host requests. Captured and serialized output is checked against its budget before yielding or completing.

`tooling/wasm-meter` owns build-time instrumentation of function and loop entries and checks every `memory.grow` before allocation. Wasm globals carry the counter and page ceiling; guest Python cannot disable the meter through tracing APIs. An abrupt Wasm trap does not unwind Rust or release wasm-bindgen borrows. The interpreter state is owned by the entire fresh Wasm instance, so generated Python bindings detach the wrapper during release instead of invoking a destructor on interrupted memory. The build verifies the pinned destructor shape before this transformation. Discarding the binding scope makes the entire native heap collectible; interrupted instances are never reused.

The Ruff dependencies remain at the versions in RustPython 0.6.0's published lockfile. Later compatible-range releases changed the AST and fail RustPython's codegen build. The application lockfile owns those resolved versions; no installed library source is patched.

Rust produces bounded read and positional-write plans from the acquired manifest snapshot. Range reads fetch complete touched blocks to verify their length and SHA-256, then return the requested bytes. Positional writes preserve untouched digest references; boundary blocks are verified before merging data, fully covered blocks require no old-content fetch, and growth creates zero-filled blocks. The native kernel owns mode, path, quota and inode checks. The Worker uploads the new immutable blocks and publishes one conditional head update. Missing or corrupt requested content fails instead of returning partial bytes. Unrequested corruption does not make an independent range read or write fetch the rest of a file.

Output persistence owns immutable `sandboxes/<id>/stdio/<sha256>` blocks, each at most 64 KiB. `run-v5` receipts retain the byte size and ordered block digests for each stream, plus result and exit status. Checkpoints upload changed blocks before their conditional receipt publication; acknowledged blocks are reused. Unpublished objects may remain after conflicts and are removed by disposed-sandbox reclamation; collecting them while a sandbox is live remains open. Page reads validate the lengths and SHA-256 digests of addressed blocks, while full process inspection reconstructs the public text output. Waiting does not reconstruct active snapshots on every poll.

The unconditional output-chunk migration decodes historical inline receipts only at its migration boundary and cuts them over with their original ETag. It preserves authority, execution deadlines, lifecycle and observations. Concurrent changes abort that receipt's migration; completed receipts carry their current format marker, allowing a later invocation to resume the remaining cutover. Runtime readers and writers accept only the current chunk-reference contract.

`src/wasm-module-bytes.json` owns the Wasm module byte budget. The API derives its base64 text ceiling from that value, file admission checks decoded bytes against it, and the Wasmi build emits the same native constant. Wasm modules are bounded to 8 MiB independently of the unchanged 1 MiB script limit. Admission rejects oversized inline or file modules before creating execution receipts; the existing guest heap, fuel, descriptor, output and Worker CPU limits still apply. The expanded size gate does not implement missing host imports required by larger published packages.

The libc metadata imports use the sandbox's current stat values, with logical allocation reported in 512-byte blocks. Private Wasmi stat records append POSIX mode and UID/GID to the 64-byte WASI record; WASI callers still receive exactly 64 bytes. Scalar host imports resume with their declared i32/i64 type and preserve their zero, minus-one or errno failure conventions. Path queries retain directory confinement and symlink-following policy, FD queries retain descriptor rights, and ownership writes validate both pointers before changing guest memory. Captured stdio is not a terminal.

`host_process.fd_dup` and `fd_dup2` share a native open description: aliases share position and file-status flags while per-descriptor close-on-exec flags remain independent. Replacing a descriptor closes its previous resource; the file cache is released only when its final descriptor closes. Captured stdin/stdout/stderr retain their stream identity through duplication and remapping, including replacing stdout with a file. Duplication preserves rights, validates output pointers before allocation, respects the descriptor quota, and excludes the private pathname preopen from the guest FD namespace. These handles live within their interpreter invocation; subprocess inheritance and pipes remain separate parity gates.

Anonymous pipes own a shared FIFO within their interpreter invocation. Each FIFO holds at most 64 KiB; writes up to 4096 bytes are atomic, larger writes may be partial, and descriptor quota bounds the number of pipes. Aliases retain endpoint identity and share status flags. Reads report EOF only after the final writer closes; writes with no reader report EPIPE. Nonblocking unavailable I/O reports EAGAIN; blocking unavailable I/O suspends under the existing capability expiry and process cancellation lifetime. Poll excludes unavailable pipe events while preserving clock subscription identity. Pipes are not seekable, do not publish file contents and are not yet inherited by separate subprocess invocations.

Scheduled jobs live in `schedules/<sandbox>/<id>.json`, with the original scoped capability and a pending occurrence marker. The same R2 put owns the record and its small scheduling metadata projection. Minute ticks list metadata in pages of 1,000 and fetch only due active records, with concurrency four. The existing process repair stays on its five-minute cadence. A conditional claim precedes admission; the process ID hashes the job key, occurrence time and execution identity seed. A replacement Worker recognizes an existing process reservation instead of replaying entry, and Queue repair handles reserved deliveries. Final schedule advancement is conditional on the claim ETag. Cancellation is a retained state transition, preserving the ID and preventing future claims; a previously claimed occurrence remains authorized to finish admission. Pending jobs retain original permissions/expiry and stop after sandbox disposal. Schedule state describes admission, while process receipts own execution results. Job quota enforcement, indexing without a global metadata scan, retained per-job history and arbitrary-crash recovery remain open.

The named `Agent` Worker entrypoint owns synchronous request-scoped tool callbacks. Its schema-derived native RPC protocol is separate from the HTTP Action inventory. It verifies the sandbox token before reserving a TypeScript run, checks tool names, count and capability expiry at each host call, and bounds callback JSON. The existing process owner persists source/output/outcome and owns timeout/cancellation. Callback functions never enter R2 or queued work. The entrypoint releases incoming callback stubs and returned callback values; the SDK releases the final RPC reply. Accepted host effects are not transactionally rolled back by guest interruption. HTTP and detached executions reject host callback calls.

QuickJS bootstrap source is TypeScript and Cargo compiles it with the shared native Rust/Oxc transpile module used for guest TypeScript. Generated JavaScript stays in Cargo OUT_DIR; authored JavaScript files are not retained. Native RPC void inputs/results use optional schema fields and the Rust guest resolves its pending Promise with the actual undefined value, without a JSON null substitution.

The native Code Mode adapter owns a scope and its process IDs per context. Ephemeral targets acquire a fresh sandbox and scoped authority; persistent targets attach with the caller's existing scoped capability. Context cleanup requests cancellation and observes terminal receipts for its own outstanding executions. Ephemeral cleanup then tombstones its sandbox; persistent cleanup leaves files and foreign processes under the caller's lifecycle. Callers own identity selection, persistent sandbox disposal and credential renewal. Callbacks are caller-owned native bindings, with no actor in a process singleton. Each execute wraps its return in a private discriminator so undefined remains distinct from null at the JSON boundary. The adapter uses Effect at the native framework Promise boundary and introduces no second application runtime.

RPC carries an optional memory ceiling into synchronous JavaScript/TypeScript execution. The Rust guest receives the minimum of that ceiling and the current head policy; this limit never enters filesystem publication or changes persisted configuration. Native binding tests replace both caller and sandbox Workers, verify retained files and fresh callbacks, reject readonly writes, preserve another queued process and compare real 20 MB allocations under 8/32 MB limits.

The bootstrap build script imports the shared transpile module directly and depends on workspace-pinned Oxc crates. This keeps one transpile implementation while separating the native build unit from the deployable Wasm compiler.

Shell `cat` and WASI commands carry byte buffers across pipelines and redirections. WASI stdin is encoded as base64 at the program boundary; observed native output supplies the next pipe or file write without decoding to text. Redirected stdout and stderr stay outside the process stream, including output acknowledged before a later WASI trap. Append preserves the existing file bytes. `cat` validates the aggregate file size before fetching contents, and command stdout/stderr are bounded by the sandbox output policy even when redirected. Rust filters receive raw bytes through a generated Wasm result object, scoped and freed after copying its output. `head`/`tail` support bounded `-n` and `-c`; `wc` validates its single option and counts raw bytes, newlines and ASCII-separated words. `sort` compares byte slices, `uniq` compares adjacent byte lines, and bounded byte-aware Rust regexes preserve matching grep line bytes. Public text result fields remain UTF-8 views; exact process bytes use the output-page API.

Ephemeral Code Mode contexts grant read/write access to their own temporary filesystem. Native guest `process.run` is restricted by the owning guest Schema to shell executions, which use the existing process reservation, output, failure and cancellation owners. JavaScript, TypeScript and Python cannot recursively acquire synchronous guest interpreters through this operation. Host callbacks remain name-scoped RPC capabilities, and workspace writes retain the caller's authorization. Ephemeral targets have an empty network allowlist; persistent targets retain the sandbox owner's policy and supplied permissions.

`bun tooling/inode-proof.ts` checks the deployed filesystem and shell through the Effect SDK using `CIRRO_URL` and private `CIRRO_API_KEY`. It exercises write-only append/truncate across a binary block boundary, zero-filled growth, shared inode ownership, alias-preserving snapshot restore, pipeline negation and ordered stdout redirections. Its scoped finalizer disposes the synthetic sandbox. This HTTP proof does not establish remote service-binding behavior or performance.

WASI poll sleeps use a minimum one-millisecond host timer while retaining the requested deadline and native Clock readings. [Cloudflare production clocks advance after I/O](https://developers.cloudflare.com/workers/runtime-apis/performance/), and submillisecond timer delays can be truncated to zero; repeatedly waiting below that resolution exhausted a deployed Worker's resource limit. The runtime rechecks the original monotonic/realtime deadline after waking, never invents elapsed guest time, and still races I/O readiness and capability expiry. `bun tooling/poll-proof.ts` compares nanosecond and millisecond sleeps against `CIRRO_URL`, retains unexpected wire status/body and the execution receipt before disposal, and checks allocation bytes as well as exit/output. Native local clock tests cover behavior but do not reproduce production's timer granularity.

Rust shell redirection plans distinguish input, stdout and stderr targets. Effect opens targets in lexical order, retaining independent inode identities and append modes. Execution faults become bounded command diagnostics before redirection publication, so a successfully opened stderr target also receives diagnostics from a later open or lookup failure. The same byte-write path applies both output streams without granting guest read authority. An error while writing an output target is reported once; it never retries an uncertain write. Each redirected stream is buffered until command completion; stdout is applied before stderr, so this does not establish original cross-stream ordering or descriptor duplication semantics.

Program preparation merges package defaults, persisted sandbox environment, then caller overrides. It validates count, UTF-8/value bounds and the serialized environment budget before runtime-specific source reads or process reservation. WASI then validates stdin and the combined argv/environment budget before executable content reads. Every archived program captures the merged map. Shell child resolution uses that snapshot; JavaScript receives only a guest-local `process.env`, and Python receives a restricted native `os.environ`/`os.getenv` module. Neither runtime inherits Worker bindings, and guest mutations do not update the root.

The environment cutover uses the administrator-only `/v1/migrations/environment-v1` endpoint. Head and process phases each scan at most 25 native R2 entries or sandbox prefixes and return a typed continuation. Each phase admits at most four object operations concurrently. A request-local native Effect Semaphore weights body decoding by object size in MiB, with eight permits; larger bodies take all permits, and checkpoint conversion takes all permits because it also reads a root. This bounds simultaneous large decodes separately from request count. Independent receipts keep their own conditional publication; shared immutable artifacts retain their digest identity. Current program metadata is inspected with native R2 `head`, without opening an unused body stream. Legacy inputs use a conditional `get` against that ETag and consume the body before digest validation/conversion. Deployment progress logs retain the typed continuation returned by each confirmed page. Legacy roots receive an empty configured map; legacy script, Python and shell artifacts receive explicit empty snapshots, preserving their historical execution inputs. Wasm input maps remain unchanged. Runtime acquisition accepts only head version 3 and program metadata `program-json-v2`; old queued artifacts and checkpoint roots defer before claim until converted. Migration verifies immutable digests and conditionally publishes receipts, preserving their authority and deadlines. Checkpoint ETags are rebased only when both the recorded prior ETag and the complete normalized root match; stale checkpoints stay stale. Partial conversion can be resumed from persisted state. Metadata conversion tests do not establish historical interpreter heap compatibility, nor do they close the existing cross-object admission/old-image race. Pre-module releases archived raw JS/TS/Python/shell source for terminal receipts. Migration verifies those digests and retains the exact bytes under `historical-source-text-v1` only when the receipt is terminal and has no retained authority, deadline or checkpoint. These archives remain non-executable. A modern JSON marker, queued status or retained authority prevents this historical classification.

`CIRRO_URL=<authorized-worker-url> bun tooling/environment-proof.ts` verifies merged count/byte limits, invalid UTF-8 keys/PATH and oversized UTF-8 values against the authenticated Worker. Each rejection must leave no process receipt or filesystem generation change; a valid override still executes. The scoped probe disposes its synthetic sandbox and never receives the R2 binding. The missing-block preflight fence is verified separately in native local R2 tests.

## WASI creation masks

The native WASI State owns one permission mask initialized to 0022. Both the published Brush read/set ABI and the libc replacement ABI validate the output pointer before mutation and return the previous low nine mode bits. Invalid read/set flags fail without changing state. Regular creation modes, anonymous temporary-file modes and directory modes pass through that mask; changing a mask does not change existing entries or descriptor rights. The private kernel applies a directory's resolved mode before publication.

Spawn copies the mask independently into the child's native State. Exec preserves the previous State's mask. The existing heap checkpoint includes the mask with the rest of the native process state; its exact-runtime digest check still prevents loading a heap from a different Rust build. A replacement-worker test parks before file creation and verifies the restored mask through both queries and actual file/directory/anonymous-file creation. Files with mode zero remain writable through their original admitted descriptor.

Published `sh` links optional terminal imports even for noninteractive execution. Captured stdio and pipe mode remain non-TTY and unattached raw-mode changes return ENOTTY. Attached `host_tty.read(pointer, length, timeout_ms)` reads the same native stdin terminal as WASI `fd_read`; it introduces no input queue or persisted record. The return value is a byte count, never a positive errno. Zero length returns zero. Zero timeout returns zero without consuming input, matching the inspected upstream runner. Other finite timeouts use the existing monotonic Effect poll deadline; `u32::MAX` waits for input or permanent EOF. Native readiness and process-family notifications wake the wait. Guest memory and read rights are validated before suspension; faults fail execution explicitly. A non-restarting caught signal ends the read with no bytes, while SA_RESTART retains the wait. Cancellation uses the existing process scope. Native tests cover finite expiry, later input, EOF, cancellation and rejected memory/rights. The digest-pinned published Brush shell runs both minimal and Reedline interactive sessions, including native cursor-query responses, bracketed paste, history recall, line clearing, a persisted file and exit status. The fixture responds with a fixed cursor position; it does not prove a rendered terminal, resize or foreground job control. This remains source-only after 0.12.1.
