# Runtime and persistence

The HTTP Worker authenticates the administrator or verifies an HMAC capability. Effect Schema decodes each request with unknown fields rejected. A scoped Effect program loads the R2 head, creates one Rust/Wasm kernel, invokes the domain operation and releases the Wasm handle on exit. Request identity and mutable kernel instances are never process globals. The compiled Wasm module is initialized once.

## Filesystem commits

`sandboxes/<id>/head.json` contains the Rust metadata manifest, generation, sandbox policy and disposal flag. File nodes contain byte size, mode and ordered SHA-256 chunk references; directories and symlinks are metadata nodes. Rust owns canonical paths, ancestor search permissions, modes, quotas and filesystem mutations. Manifest version 3 owns unique inode identities, UID/GID metadata, nanosecond access/modification/change timestamps, packages and command bindings. A single metadata entry per path carries those attributes; Rust validates its key set against the node tree. Writes preserve inode identity, rename moves it, replacement retires the target identity, and allocation never reuses an inode. New nodes initialize timestamps from the native Effect clock; mutation updates modification/change times and affected parent directories. Reads use a no-atime policy.

`sandboxes/<id>/blobs/<sha256>` contains immutable 256 KiB data blocks. The trusted Worker hashes inputs with Web Crypto and verifies block digests on reads. Access goes through the scoped native R2 binding; guests cannot address arbitrary bucket objects.

A write validates its filesystem mutation, uploads all required blocks with bounded concurrency, then publishes the new head only if the original ETag still matches. The ETag operation is the visibility boundary. A failure before it leaves the previous filesystem visible. A failure after a successful head write does not undo the committed operation. A racing writer gets a conflict instead of a silent lost update. Read operations retain their original manifest and read its immutable blocks, yielding a consistent snapshot.

Multi-file writes execute in input order, create parent directories and report domain failures per file. Each batch is limited to 128 entries and 16 MiB total decoded content. Rust prepares each mutation without changing metadata, the Worker uploads its blocks, then Rust applies the mutation. Successful entries and any created parent directories publish together with one final ETag check; a conflict rejects the entire publication. Infrastructure failures stop the batch before publication, while uploaded orphan blocks may remain. Empty batches do not advance the generation. Multi-file reads retain one snapshot, bound aggregate content to 16 MiB and return missing/inaccessible paths as per-file errors. Files are read sequentially with block concurrency four. Recursive listing traverses kernel metadata without per-entry R2 reads, respects depth and excluded names, follows a root alias and lists child symlinks without descending through them.

Rename modifies the metadata tree and publishes one new root; it does not rewrite file content. Shell scripts retain one private kernel and publish their filesystem changes in one commit after command execution. JavaScript/TypeScript tools commit each filesystem action independently. Consequently, a failed guest can have already committed files, while a rejected shell commit leaves its private changes invisible.

Full bounded metadata is loaded per operation. That is acceptable for the initial validated workloads but is not proof of performance at 16,384 files. Paged metadata, random-access writes, hard links, ownership/timestamps and safe block reclamation remain unimplemented.

## Guest boundary

One ordinary Worker loads precompiled Rust/Wasm modules for its filesystem kernel, QuickJS, Oxc and WASI/Wasmi. JavaScript runs in a fresh QuickJS runtime with its own heap, stack ceiling, interrupt budget and microtask ceiling. TypeScript is transpiled by Oxc before entering that runtime. Each module compilation owns a fresh Wasm instance with 64 MiB maximum linear memory; generated native bindings are instantiated through a build-time factory. This contains compiler stack/memory traps instead of retaining a poisoned instance across requests. Guest Wasm is interpreted with Wasmi fuel and memory limits; it is never dynamically compiled using the platform WebAssembly API.

Rust exposes a step/respond protocol for asynchronous capability calls. Effect validates each requested action and executes it using the original trusted sandbox identity, expiration and permission set. Guest JavaScript receives only JSON responses and no host JavaScript references. Capability functions resolve guest promises through native QuickJS handles; dropping an execution releases its pending handles and runtime. No native platform imports, Worker environment, R2 binding or direct network function exist inside QuickJS.

Rust Oxc discovers static imports and reexports and rewrites dynamic imports to the native asynchronous promise bridge. The Worker resolves canonical paths through the Rust kernel and reads immutable blobs from one filesystem snapshot, respecting read permissions and following symlinks. Each first dynamic import acquires the current authorized snapshot, so files created during guest execution can be imported. Preloaded graphs preserve native ESM cycles and module identity. Inline script/evaluation and file entry points use the same graph owner. Graphs are limited to 128 modules, 128 imports per module, 1 MiB per module source and 8 MiB serialized data. Computed and literal dynamic imports resolve with native QuickJS module namespaces, including function exports and cached identity. Concurrent requests for the same module share that cache. Package/Node resolution, import attributes/URL query identities and execution options remain pending. Preflight failures do not reserve execution IDs. Initial source digests identify the preflight graph. When execution terminates, including controlled CPU/memory failures, imported source snapshots are archived and the terminal receipt points to the complete captured graph. A platform crash before that commit can still leave the initial running receipt.

`interruptBudget` measures interrupt callbacks, not CPU milliseconds. Wasmi uses 1,000 fuel units per budget unit. Memory limits are per guest; the Cloudflare Worker also retains its native aggregate CPU/memory limits. QuickJS has a 512 KiB stack ceiling, 10,000 microtasks and 256 capability requests. Serialized output is bounded. Python execution is explicitly unavailable until a bounded interpreter replaces the removed Dynamic Worker path.

The tool contract excludes administration, process creation and lifecycle mutation. Network calls require both the `network` grant and an exact sandbox policy hostname. Only HTTPS GET is implemented. URL credentials, nonstandard ports and IP destinations are rejected. Redirects are returned without following them. Network bodies and request/guest responses are read through bounded native Effect streams.

Wasm accepts `_start() -> ()` for [WASI Preview 1](https://github.com/WebAssembly/WASI/blob/a2b96e81c0586125cc4dc79a5be0b78d9a059925/legacy/preview1/docs.md) commands or `run() -> i32` for standalone guests. Each execution owns a fresh Rust Wasmi host instance and its native Wasm memory; freeing the guest releases file buffers and makes the host instance collectible. Native generated bindings are scoped by a build-time factory, retaining their original types. Wasmi interprets the submitted module inside this precompiled instance, with fuel, linear-memory, table and instance limits. The platform never compiles submitted guest bytes.

Implemented Preview 1 operations cover preopen discovery, descriptor rights, file open/create/truncate, vectored read/write, positional read/write, seek/tell, close, sync/datasync, captured stdout/stderr, process exit, clock resolution/time and cryptographic entropy. Argument/environment syscalls expose the supplied UTF-8 strings with native pointer arrays and NUL terminators. Stdin reads preserve a cursor and return EOF after its byte stream is consumed. No Worker environment variables are inherited. Unknown process options are rejected. Unsupported registered syscalls return `NOTSUP`; unsupported imports or signatures fail instantiation. File/path stat, directory enumeration, mkdir, rename, unlink/rmdir and symlink/readlink are implemented. Directory cookies index a captured sorted snapshot, and truncated buffers preserve the native dirent layout with persisted inode identities. Append/nonblocking flags are retained on descriptors; buffered regular file/directory I/O completes immediately. The [Preview 1 setter contracts](https://github.com/WebAssembly/WASI/blob/a2b96e81c0586125cc4dc79a5be0b78d9a059925/legacy/preview1/docs.md#fd_filestat_set_times) cover descriptor resizing and descriptor/path access and modification timestamps. Resizing preserves the cursor, zero-fills growth and restores the prior buffer on an errno response. Each syscall checks its own descriptor right and the sandbox write grant. Timestamp values cross the host boundary as decimal strings and enter native `u64` values without JavaScript numeric rounding. Explicit and NOW flags update only selected fields; NOW uses the request's trusted Effect clock and a zero flag mask leaves all times unchanged. Symlink lookup flags retain directory confinement. The same operations apply to detached open descriptions without recreating directory entries. Additional sync flags, hard links, polling, sockets and software-specific extensions remain open.

WASI owns one private filesystem snapshot, reusing the process's acquired Rust kernel. File mutations validate permissions and quotas and upload immutable R2 blocks before reporting successful writes. Their metadata publishes together when execution finishes; an explicit sync publishes a checkpoint and advances the session ETag. An unsynced trap leaves private changes invisible, while already published checkpoints survive later traps. A conflict stops execution and preserves the competing root. Reads share cached file bytes between descriptors without repeated R2 downloads. A separate cache identity owns open file descriptions; replacing or unlinking their directory entry detaches the old cache, and later writes update only that live description. Rename moves linked cache paths and open directory bases. Detached files retain their real inode and metadata, report zero links, and disappear when the last descriptor closes. The cached bytes are in the trusted interpreter, outside the guest's linear memory. Preparing a write-only file uses kernel write permission; guest reads still require both its descriptor read right and the capability's read grant. Directory descriptors reject lexical and symlink escapes. Capabilities are checked before host operations and final publication.

WASI limits include 128 directory/file descriptors including the root preopen, three stdio descriptors, 16 MiB aggregate cached file bytes, 128 iovecs and 256 host requests. Closing a file's last descriptor releases its cache allocation. Buffer exhaustion, invalid pointers, quotas and narrowed descriptor rights return native errno values. Host request-budget exhaustion traps instead of permitting an unconfirmed buffered mutation to continue. Reads currently load complete files, and each write rehashes its current contents. Ranged block access and large/mixed/concurrent production workloads remain performance gates.

The shell is a trusted bounded interpreter, not arbitrary native process execution. Rust owns parsing and text commands, while Effect orchestrates filesystem calls and commits. It is not a complete POSIX shell. Durable access uses the scoped capability API; Node filesystem compatibility and Python execution remain pending.

## Execution receipts

`sandboxes/<id>/code/<sha256>` stores JSON programs. A Wasm program captures source bytes as canonical base64, full argv, the supplied environment and stdin. Its digest identifies the complete input, not just the binary. File execution snapshots the binary before creating its receipt; later file edits do not change that artifact. `runs/<id>.json` stores a unique execution ID, language, source digest, timestamps, lifecycle status and terminal output. The initial receipt is conditionally created. A duplicate ID is rejected before execution. Completion conditionally replaces only the original running receipt. Run summaries are encoded into native R2 custom metadata at the same write, so paginated listings fetch only the requested metadata page and do not download each execution output. Cursors and limits pass directly to the owning native API.

A failed transport does not authorize repeating the same execution or deleting its receipt. An interrupted host can leave a `running` receipt even if the guest has stopped. There is no crash recovery, durable spawn, signal handling or reliable cancellation contract yet. Results and filesystem writes are not one cross-object transaction.

Disposal publishes a tombstone in the same head and invalidates future reads/writes/tool calls. It does not reclaim data or instantly terminate already-running guest CPU. Policy changes use the same root commit, require management permission and preserve files. Execution-budget changes apply to subsequently created guest runtimes; subsequent tool calls read the current network policy.

## Infrastructure and production gate

Alchemy declares one sandbox Worker and its R2 object bucket. The filesystem migration upgrades version 1 or 2 manifests to version 3 after the execution-policy migration. It preserves generations, existing inode identities, data, timestamps and tombstones; version 1 receives deterministic identities and zero historical timestamps. Ownership defaults to zero, and the initial package and command catalogs are empty. Only version 3 manifests enter runtime acquisition. Conditional ETags guard publication; repeated migration is idempotent, and a concurrent head change aborts. During the cutover, old manifests reject reads until the deployment action converts them. The endpoint uses native R2 bindings because the installed Alchemy HTTP bucket client does not forward conditional PUT options. Deployment migration requests retry only HTTP 404 for a bounded interval while a newly added endpoint propagates. Other failures stop the deployment action. Runtime imports of provisioning types remain erased. Local integration tests use native Miniflare workerd/R2 and its actual HTTP server.

The deployment action also runs the Wasm-input migration on every deploy. It converts old raw Wasm artifacts to the current JSON program contract with empty argv/environment/stdin, preserving historical defaults. It verifies the old source digest before conversion, writes the immutable new artifact, then conditionally rewrites each receipt and its native listing metadata. A concurrent receipt update aborts rather than overwriting it. Receipts without listing metadata are recovered from their bounded body. Modern artifacts carry the producer's `program-json` metadata marker and are skipped on later runs. Old immutable objects remain retained until safe reclamation exists. Runtime execution uses only the current program shape.

The user selected the `minutei` Alchemy profile for development and deployment. Local test results do not establish deployed behavior, remote CPU enforcement, production latency or a successful CI run; record those gates separately after executing them.

## Software packages

The Rust kernel decodes the upstream v2 `.aospkg` wire format using records generated from its pinned BARE schema. Header, embedded versions, bounded inventories, canonical paths, byte ranges, command targets, directory projections and environment values are validated before installing. Complete consumption and native re-encoded lengths reject trailing bytes, duplicate map keys and lengths that would wrap in wasm32. Package and file SHA-256 identities derive from actual bytes.

The version 3 manifest owns the package catalog, command bindings and file ownership. Installation stages a private snapshot, validates namespace and byte quotas, uploads deduplicated immutable blocks, then conditionally publishes the filesystem and catalog together. A losing ETag publishes neither. Projection conflicts and duplicate package versions reject the staged snapshot. Raw source files can change afterwards without changing installed bytes. Blocks remain retained until safe reclamation exists.

Package directories and their declared aliases are readonly for ordinary filesystem, shell and WASI operations, including permission/time changes and removal or relocation of an ancestor. Only the package domain mutates these projections. Removal deletes its package subtree and declared mounts; command ownership falls back to the first remaining provider. Package metadata serializes canonically so migrations do not rewrite an unchanged catalog.

`process.execFile` resolves an installed command or a sandbox path and currently executes WASI binaries. Explicit caller environment values override first-provider package defaults; Worker bindings are never inherited. Other command runtimes, guest working directories, default release packages, large package streaming and reclamation remain open.

The shell resolves external executables using the package-provided PATH or its default directories; a qualified executable path resolves against the shell's current directory. Executable mode checks distinguish missing commands (127) from inaccessible commands (126). Shell builtins retain precedence. Standard input from a pipe or redirection enters the WASI byte stream, and captured output flows into the next pipe or output file. The guest's own libc working directory is currently its root; changing the shell directory affects executable lookup, and child working-directory semantics remain a parity gate.

The storage publication owner updates the request-local session's manifest and ETag only after a confirmed R2 write. WASI retains a snapshot of its entry state and each acknowledged checkpoint. On failure it restores that snapshot within the same Rust kernel, preserving earlier shell changes and synchronized guest changes without retaining unsynchronized guest mutations. Shell recovery can continue against the updated session. Publication conflicts and expired capabilities abort the shell instead of continuing with stale authorization or state. Infrastructure failures propagate; an uncertain remote write is not treated as rolled back.
