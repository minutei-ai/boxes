# AgentOS parity inventory

Reference: [AgentOS README at the inspected commit](https://github.com/rivet-dev/agentos/blob/4d48628304c1ddedafc9d55f60752093fcf6f3d2/README.md). The scope is behavioral parity, not matching names or publishing endpoints that silently ignore inputs. Unsupported actions fail schema validation.

Experimental SDK/runtime 0.18.0 is published and deployed. The [delivery evidence](evidence/sdk-0.18.0-delivery.json) records exact public downloads, CI, unconditional Alchemy migrations and native production service bindings. Smart Placement is enabled and confirmed through the Cloudflare settings API; it applies to fetch handlers rather than the Agent RPC entrypoint. Remote proofs cover terminal controls and active/settled PTY discovery, the rebuilt shell cwd contract, and minimal/Reedline partial-line recovery through real checkpoints. Minutei validation is tracked separately in the delivery record. Synthetic cursor replies do not establish terminal rendering, arbitrary-crash restoration or production latency. Default software provisioning and the remaining parity gates stay open.

Production delivery of this candidate is not yet proved.

## Completion gates

1. Port the missing process/terminal and language contracts with real native-runtime tests. QuickJS does not provide Node compatibility.
2. Complete the Rust WASI syscall plane, process options, shared durable files and software packages. The upstream browser bridge uses SharedArrayBuffer/Web Workers; Cloudflare Workers has no threading and cannot use it unchanged.
3. Complete language package resolution and filesystem integration, then compare actual upstream fixtures. Evaluate native Rust compilation and native Cloudflare runtime support before adding alternate execution infrastructure.
4. Implement durable execution recovery, cancellation, stdio replay, schedules and previews with R2 as application data owner. Define and test effects under interruption/reconnection. Cover handover overlapping child admission and steady-state waits.
5. Validate Queue backlog/fairness and performance at large file/process inventories, CPU/memory exhaustion, concurrent agents and cold language startup.
6. Deploy using the minutei profile, validate the same flows against the remote Worker, and verify remote CI independently.

The current implementation passes the implemented-boundary tests; these gates are open. There is no total-parity or production-readiness claim.

`bun run software:proof` validates both published jq and sh packages against `CIRRO_URL`, using the [same catalog pins](../src/default-software.ts) and [shell cases as the native tests](../tests/fixtures/published-software.ts). Its scoped sandbox is disposed before the report is printed. Host libc imports support one-shot file creation modes, hidden pathname preopens that survive closing fd 3, and anonymous temporary files with descriptor lifetime, sandbox grants and readonly package guards. Direct I/O is explicitly unsupported; network send/recv on regular files returns NOTSOCK. This does not establish compatibility for other release packages.

Root filesystem export preserves binary files, modes, ownership and symlink targets from one confirmed manifest with an exact serialized byte limit. Native workerd tests cover guest access, replacement Workers, concurrent batch writes, permission failures and corrupt R2 blocks. Creation can import the same filesystem snapshot, with one exclusive head publication. Invalid paths, graph relationships and base64 are rejected before blob writes. Interrupted or losing creations may retain unreferenced immutable blobs, while their incomplete root is never published. Creation and in-place restore share validation and reconstruction. Restore requires write and manage, allocates fresh inode identities, clears software catalog registrations and publishes once against the original head ETag. Native service-binding tests and concurrent restore tests verify complete roots; a replacement Worker refuses to resume a checkpoint with an obsolete filesystem generation. Imported snapshots restore filesystem entries; live processes and software catalog state have separate owners. Mounts remain open.

WASI Preview 1 `fd_advise` accepts the six standard hints after checking descriptor rights, file type, enum and unsigned range overflow. Advice does not change bytes, offsets or file size in the in-memory guest cache. The native Cargo fixture verifies this ABI in workerd, including descriptors opened without the advice right. `bun run advice:proof` verifies the same fixture and retained file bytes against `CIRRO_URL`. This closes one import gap; CPython still requires other WASI imports and a validated standard-library filesystem.

WASI [`fd_fdstat_set_rights`](https://github.com/WebAssembly/WASI/blob/snapshot-01/phases/snapshot/docs.md#fd_fdstat_set_rights) reduces base and inheriting rights atomically and rejects added bits with NOTCAPABLE, including unsigned high bits. Stdio uses the same effective descriptor rights as files and pipes; reads, writes, flag updates and polling enforce them. Duplicates and renumbered descriptors retain their own reduced rights. `path_open` checks creation/truncation rights and inheriting limits. Native workerd tests verify retained bytes, failed updates without partial reduction, closed descriptors, and a 31-second guest suspension with Queue checkpoint handover to a replacement Worker. Rights live in existing descriptor state; there is no new persisted format. An alias retained before reduction remains independently authorized; replacing a descriptor through existing duplication operations does not resurrect its old capability.
