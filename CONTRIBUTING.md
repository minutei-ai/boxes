# Contributing

Shell comparison tests require Bash in POSIX mode (`bash --posix`), so their reference behavior does not depend on the host's `/bin/sh` implementation. Bash 5.2 and 5.3 differ when unsetting readonly variables and rejecting invalid readonly names. Those cases assert Boxes' fatal-error contract directly, including stderr and exit status; they do not depend on the host oracle. CI records its Bash version. This reference does not establish complete POSIX shell conformance.

The software catalog at `src/default-software.ts` owns package pins for deployment, tests and proofs. `tooling/software-artifacts.ts` reuses immutable packages under the native temporary directory, keyed by SHA-256. Every read checks the full size and digest. A successful download is verified before atomic rename publishes it, so concurrent consumers cannot read a partially written package. A missing entry downloads the actual public package; a corrupt entry fails explicitly. Alchemy owns publication of the base into R2. Request runtimes never download software as an initialization step.

Native fixtures use the explicit bare `SOFTWARE_BASE: null` configuration unless testing the default image. The default-software suite uses the real Rust-prepared sh/jq subset of the pinned catalog, native R2 and service bindings, verifies zero private package copies, one-block copy-on-write, read/execute-only clients, readonly projections, private isolation, missing/corrupt public content, disposal/reclamation and closure before replacement. The real Alchemy dev topology is a separate operational proof: its deploy-time R2 gateway has a different lifetime from the running Worker. Do not replace that proof with manual fixture seeding. Default software publication verifies existing block bodies with streaming SHA-256, repairs missing or corrupt bytes and publishes the manifest last. Reads and writes remain serial: the installed Alchemy local client opens a separate workerd per operation, and parallel cold reads as well as writes reproduced `SQLITE_BUSY`. The [publication proof](docs/evidence/software-publication-reuse-local.json) records native Alchemy/workerd/R2 checks, including unchanged native object versions on reuse. Run `bun run software:publication:proof` after building the kernel; it selects a fresh local dev stage, publishes three small pinned upstream packages, removes/corrupts three blocks, verifies repair and then remains in the native Alchemy dev watcher. Stop that proof with Ctrl-C after its `Verify` action succeeds. The fixture rejects non-dev execution before provisioning. Its elapsed time and uploaded-byte counters are local deployment evidence, not production request latency or an AgentOS cost comparison.

Python source builds currently require Linux x64. The build provisions digest-pinned Binaryen 133, extracts only its native compiler and verifies cached compiler/output bytes. `target/python-asyncify` retains input/binary/flag-keyed transformed engines; CI restores the same cache. A changed Python build invalidates retained heap compatibility and requires explicit context reset. The combined retained binding proof reserves memory for its frozen stdlib, filesystem modules and suspension stack; its setup is separate from product defaults and the negative memory-ceiling tests. The [trap investigation](docs/evidence/python-trap-diagnosis.json) identifies a correctly rejected growth at the former proof ceiling. Keep permission assertions and bounded-resource probes intact when changing that workload.

Install the pinned Bun dependencies and wasm-bindgen CLI, add both `wasm32-unknown-unknown` and `wasm32-wasip1` Rust targets, and run `bun run check`. Formatting is checked with `bun run format:check`. The test script runs files in two isolated native Bun worker processes, preserving test order inside each file. Build and Cargo fixture generation finish before those workers start; each suite retains its native Alchemy runtime, R2 and Queue lifetimes. R2 inspection connects to the native platform-proxy handler embedded in the Worker that owns the bucket; the outer inspection Worker does not open that bucket again. Opening the same local store in two workerd instances gave readers a separate blob lifetime from writers. The declared Cloudflare runtime patch exposes its existing Worker handler and compiler-emitted declarations. Remove that patch when the installed provider exports an equivalent embeddable handler, and switch both fixture imports in the same cutover. [Native ownership evidence](docs/evidence/native-r2-owner-local.json) records the failing concurrent reads, owner trace and verification. [Local execution evidence](docs/evidence/native-tests-parallel.json) records the serial and two-worker runs and their limits. Update the applicable parity row only after a real runtime test demonstrates behavior. New guest operations must test authorization, isolation, failure/interruption and persisted state. Tests must not replace native R2 or execution with mocks. All Worker suites and local benchmarks use Alchemy’s native workerd runtime, R2 and Queue bindings. Queue events and timed HTTP requests drive Effect TestClock within their own request context; advancing callbacks from another request violates workerd isolation. HTTP clock advancement waits for the first native sleep to register. The native RPC timeout probe uses a one-second request budget so cold admission can reach the callback; its callback remains pending beyond that deadline, and a native latch confirms completion after the guest has failed. This checks accepted callback lifetime rather than racing a 25 ms cold start. It does not change production limits. The continuation test retains the 25-second HTTP deadline and a 31-second WASI sleep, checkpoints at 30 seconds and resumes in a replacement Worker. Active PTY recovery fixtures park at the existing 30-second lease with partial canonical input or raw bytes retained in the native heap. The Queue clock driver advances after the first acknowledged output. Multi-child foreground admission and delayed poll/stop fixtures verify that the final sleep ends at the absolute lease deadline. Raw fixtures also verify their pre-checkpoint consumption marker. Replacement runtimes use the saved clock and the same native R2 store, with each prior runtime closed before the next starts. Heap-restoration fixtures count actual R2 page reads through the native binding and corrupt a shared page to verify validation before native resume. Each runtime owns a unique Queue broker. Before-entry replacement tests use the native producer delivery delay; R2 receipts remain the durable recovery owner. Terminal resize tests use the platform proxy’s native service binding and a real TypeScript guest tool call, with SIGWINCH handlers and stdin EOF. Migration tests downgrade fixture input heads to their historical shape, drive bounded pages and replay after conversion, retaining resized-head ETags. Network fixtures are TypeScript/Effect Workers routed through the native runtime plugin. Rust fixtures are compiled through Cargo so unchanged recipes reuse native incremental artifacts. The native Rust CI cache retains generated artifacts even after a failed check; validation still runs on the next commit.

`bun run software:defaults:proof` prepares the complete pinned default image and exercises each upstream software family through native local R2 and default service bindings, without installation authority on the execution client. It owns isolated local storage and disposes/reclaims the sandbox. This broader proof downloads the full content-addressed packages; the ordinary integrity/isolation suite keeps the two-package fixture to bound cold downloads. Deploy-time publication remains a separate Alchemy lifecycle proof.

`bun run software:storage:proof` inspects the deployed Worker settings and its bound R2 bucket using the native Cloudflare SDK with profile `minutei`. Supply `ALCHEMY_PROFILE`, `CIRRO_WORKER`, `CIRRO_BUCKET`, `CIRRO_URL` and `CIRRO_API_KEY` through the execution environment. It verifies Smart Placement, creates an isolated sandbox, checks one head and zero private software blobs, then disposes/reclaims it and verifies the shared image survives. The full-image local and remote binding proofs share the fourteen cases in `tests/fixtures/default-software-proof.ts`; named Agent RPC is verified separately.

Run `bun run bench` for performance changes. `bun run bench:metadata` compares scalar and bulk snapshot metadata collection at 1,024, 4,096 and 16,384 entries, alternating five samples per algorithm and verifying identical metadata digests. It measures the Bun-hosted kernel Wasm and Effect Schema decoding, not end-to-end Worker or production latency. Record artifact size, workload, distributions and environment. A local workerd benchmark does not establish Cloudflare production latency. Keep fixtures synthetic; private HTML, source code and credentials stay outside the repository.

`bun tooling/benchmark-pty.ts <reference-runtime-directory> <current-runtime-directory> <output.json>` compares cooked PTY ingestion in native Alchemy workerd. Each request runs 16 rounds of 64 plain lines and 64 lines with erase, control-byte echo and CR translation through real guest master/slave descriptors. It checks every accepted byte count, canonical line and echoed byte. Eight fresh-R2 phases alternate ABBA then BAAB, discard ten warmups and retain 25 samples each. The report includes fixture and runtime hashes. Preserve all phases and report host variation; local elapsed time does not establish production latency or billing. Native workerd/Alchemy and Cargo use the process temporary directory; set `TMPDIR` to a writable scratch directory when the host's default temporary filesystem is quota-limited.

`bun tooling/benchmark-shell.ts <reference-runtime-directory> <current-runtime-directory> <output.json>` compares two extracted, validated runtime archives in native Alchemy workerd. It alternates eight fresh-R2 phases (ABBA then BAAB), with ten warmups and 25 samples per phase. Each request runs 64 shell reads followed by `true`, using 128 environment entries below the 64 KiB contract limit. Every sample validates the complete output. Retain every phase and raw sample; shared-host results do not establish production latency or cost.

Maintain executable contracts at their owner. `src/contracts.ts` owns the external Effect Schema API; `crates/kernel` owns serialized kernel persistence and its invariants. Alchemy resources live in `src/resources.ts` and `alchemy.run.ts`. Runtime imports from provisioning must remain type-only.

`409` conflicts require reading current state before deciding to retry. A lost response does not roll back earlier writes. Guest side effects and execution receipts do not currently form an atomic multi-object transaction; do not hide this by replaying submissions.

The [SDK delivery evidence](docs/evidence/sdk-0.12.0-delivery.json) separates validated artifacts, publication and remote deployment. The [lifetime ETag evidence](docs/evidence/lifetime-etag-local.json) records conditional lifetime checks and their local latency limits.

Before publishing SDK/runtime archives, run `bun run package:proof <sdk.tgz> <runtime.tgz>` against the exact files to upload. It checks their matching identities and licenses, consumer declarations, public exports and native binding behavior without provisioning remote resources.

`bun run minutei:proof <minutei-checkout> <runtime.tgz>` compiles the actual Minutei Code Mode/tenant fixtures against the consumer's installed SDK and runs them against the exact runtime archive through a native Agent service binding. It verifies conversation retention, authority/isolation, cleanup recovery and current filesystem/shell features without changing the consumer dependencies. The proof owns a child process with private native Alchemy registry and data directories; it requires the consumer checkout and installed dependencies, but no deployment credentials. History Queue consumption, browser authentication and model behavior are outside this gate.

Before claiming release readiness, close the completion gates in `docs/parity.md`, verify remote CI, deploy through Alchemy and prove the behavior against the authenticated remote Worker. Never publish private authentication configuration or mutate another project's infrastructure.

`bun tooling/process-repair-proof.ts` holds one native Queue consumer on WASI stdin, admits queued work, exercises administrator repair and scoped denial, then confirms one file append and collects its root. It uses the compiled SDK and external `CIRRO_URL`/`CIRRO_API_KEY`; this verifies transport behavior rather than R2 billing.

`bun tooling/active-disposal-proof.ts` runs a synthetic WASI program that acknowledges entry before a 31-second native poll. It disposes the sandbox while the original HTTP execution is pending, verifies cancelled completion and retained output, then checks public process reads remain denied and collects its disposed fixture. It also inspects the persisted default inline recovery deadline before disposal. `bun tooling/shell-parameters-proof.ts` verifies shell parameters, variables, readonly attributes and HOME expansion. Both use the compiled Effect SDK and external `CIRRO_URL`/`CIRRO_API_KEY`; they own isolated sandbox IDs and disposal scopes and do not provision Workers or proxies.

`bun tooling/benchmark-lifetime.ts <reference-runtime-directory> <current-runtime-directory> <output.json>` compares native lifecycle checks with 4,096 seven-byte files per sandbox. It owns eight fresh R2/workerd phases in ABBA then BAAB order, writes files in serial native batches of 128, discards ten warmups and retains 25 validated JavaScript execution samples per phase. Retain the complete phase and sample data; this measures local end-to-end warm execution, not R2 request billing, cold starts, production latency or maximum memory.

`bun tooling/benchmark-write-files.ts <reference-runtime-directory> <current-runtime-directory> <output.json>` compares batches of 128 new files with distinct small contents in native Alchemy workerd and R2. Eight fresh-runtime phases alternate ABBA then BAAB; each phase discards four warmups and retains twelve samples. Every request checks ordered acknowledgements and reads three sampled files outside the timed interval. Quantiles use nearest rank. Retain every phase and raw sample, identify both artifacts and report host variability; this does not measure production latency, peak memory or R2 billing.

`bun tooling/benchmark-filesystem-lifetime.ts <instrumented-reference-directory> <instrumented-current-directory> <output.json>` compares two built `clock-worker` fixture directories with the native filesystem-usage counter. Build and snapshot them serially; both must have identical five Wasm assets, while the filesystem Effect lifetime changes. Eight fresh Worker/R2 phases alternate ABBA then BAAB. Each seeds 1,024 one-byte files, discards two warmups and retains five requests of 64 absolute Python pathname stats. Every output, full-head-read count and zero head-write result is checked. The counter forwards the actual native R2 calls. Kernel memory records linear-memory capacity high-water, not RSS, live allocations, total Worker memory or Python heap. Request times exclude setup, startup and RPC transport. Retain every phase and sample; local elapsed times do not establish production latency, CPU, billing or an AgentOS cost advantage. The native regression bounds this specific workload at eight MiB of kernel capacity while preserving real reads and disposal observations.

`bun run software:proof` verifies the digest-pinned published sh/jq packages and the shared direct/spawn/exec shebang cases and descriptor execution cases against an authenticated deployed Worker. Each script must preserve argv/environment/stdin and persist its own file marker. Descriptor cases retain access after rename/unlink, verify failed close-on-exec admission and confirm that failed scripts do not replace the last file marker. Its scoped finalizer disposes and reclaims the synthetic sandbox before the success report is printed. The native binding proof exercises the same script cases through the service binding alongside callbacks and persistent contexts, and also requires scoped reclamation.

Deploy migrations use Effect HttpClient with a dedicated connection per page and a 120-second deadline covering request, response body and decoding. Only typed transport failures retry, at most twice, against the same encoded page cursor; status and Schema failures propagate. Versioned migration handlers re-read current records and skip already converted data. Alchemy persists the action as a whole, so a failed action resumes against persisted records rather than retaining its in-memory page counter.

Host-side HTTP tests that mix SDK/native proxy calls with raw controlled-clock requests use native FetchHttpClient RequestInit and fetch connection lifetimes. Keep the real handler/status/body checks: a transport failure must never count as an expected authorization failure. The [local transport evidence](docs/evidence/local-http-transport.json) records the pooled-request reproduction and bounded differential checks; it does not establish that every network failure is eliminated.

`bun tooling/shell-cwd-proof.ts <sh.wasm|sh.aospkg>` validates a compiled shell through native Alchemy workerd service bindings and R2. Package input additionally exercises digest-pinned software installation, catalog command resolution and readback of the installed binary and notice files. It covers direct relative exec, absolute exec, symlink cwd, an adulterated `PWD` and an empty environment. The original published shell fails the direct case; the Rust patches and pinned build recipe live in [tooling/guest-patches](tooling/guest-patches/README.md). This explicit local guest build/proof is separate from ordinary tests and does not publish or replace the digest-pinned package. Ordinary tests build the native Rust package builder once and exercise its output through the compiled kernel decoder, including deterministic output, long tar paths and rejected notice symlinks.

Published-shell recovery tests answer observed terminal cursor queries through native stdin writes. Their Queue clock driver waits for acknowledged partial-line output before advancing to the original handover deadline; small native TestClock steps allow terminal negotiation to proceed. Other fixtures keep their existing first-output trigger. Both minimal and Reedline sessions close the original Worker before restoring the R2-backed heap in a replacement, verify the partial command and one file append, then replay the Queue delivery. The native clock-budget regression separately checks that repeated time observations preserve the I/O budget, randomness still exhausts it and a clock loop remains fuel bounded.

`bun tooling/published-terminal-proof.ts <binding|http> <minimal|reedline>` exercises the pinned published shell against `CIRRO_URL` and, for binding, a native Alchemy preview consumer of `CIRRO_WORKER` compiled against `CIRRO_SDK_DIRECTORY`. Use the `minutei` profile. The proof answers observed cursor queries, writes a partial command, resizes the terminal, waits for a new real checkpoint and completes the command once with exit code 7 and one file append. Its sole writer advances offsets only from confirmed input receipts; uncertain writes fail instead of replaying. The scoped finalizer disposes and reclaims its sandbox. Cursor replies are synthetic terminal input, so this is not rendered-terminal proof. Production checkpoints demonstrate native handover/resume; the local replacement test separately proves closure of the original Worker. Observation timeouts and final completion mismatches retain the observed output, process record and operation timings in the same typed failure. The native binding returns that Schema through the preview response; the HTTP tool logs its encoded JSON while preserving the failure. Successful proof reports retain those operation timings too, so intermittent failures can be compared with completed runs.

`bun run bench:python <reference.wasm> <candidate.wasm> <output.json>` compares metered native Python `begin`/`step` calls in Bun. It checks matching import/export descriptors and every result, owns one interpreter per phase, alternates eight ABBA/BAAB phases, and discards three warmups and retains fifteen measured samples per workload. The report contains every measured sample, fuel, memory high-water marks and binary/source digests. Construction, workerd/R2, cold starts and billing are excluded. Compare fuel as well as elapsed time: definition classification adds a native parser pass and must not be described as free.

`bun tooling/python-memory-proof.ts <output.json>` measures three retained Python executions through native Alchemy workerd and R2, closing each Worker before the next starts. The report records logical pages, physical pack reads/puts, workload and Python binary digests, results and per-request elapsed time. Pair it with the matching reference workload; a single sample per phase does not establish a latency distribution or production billing. The [local pack evidence](docs/evidence/memory-packs-local.json) retains the reference and packed reports and their identical outputs.
