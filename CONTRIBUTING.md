# Contributing

Install the pinned Bun dependencies and wasm-bindgen CLI, add both `wasm32-unknown-unknown` and `wasm32-wasip1` Rust targets, and run `bun run check`. Formatting is checked with `bun run format:check`. The test script runs files in two isolated native Bun worker processes, preserving test order inside each file. Build and Cargo fixture generation finish before those workers start; each suite retains its native Alchemy runtime, R2 and Queue lifetimes. [Local execution evidence](docs/evidence/native-tests-parallel.json) records the serial and two-worker runs and their limits. Update the applicable parity row only after a real runtime test demonstrates behavior. New guest operations must test authorization, isolation, failure/interruption and persisted state. Tests must not replace native R2 or execution with mocks. All Worker suites and local benchmarks use Alchemy’s native workerd runtime, R2 and Queue bindings. Queue events and timed HTTP requests drive Effect TestClock within their own request context; advancing callbacks from another request violates workerd isolation. HTTP clock advancement waits for the first native sleep to register. The continuation test retains the 25-second HTTP deadline and a 31-second WASI sleep, checkpoints at 30 seconds and resumes in a replacement Worker. Each runtime owns a unique Queue broker. Before-entry replacement tests use the native producer delivery delay; R2 receipts remain the durable recovery owner. Network fixtures are TypeScript/Effect Workers routed through the native runtime plugin. Rust fixtures are compiled through Cargo so unchanged recipes reuse native incremental artifacts.

Run `bun run bench` for performance changes. `bun run bench:metadata` compares scalar and bulk snapshot metadata collection at 1,024, 4,096 and 16,384 entries, alternating five samples per algorithm and verifying identical metadata digests. It measures the Bun-hosted kernel Wasm and Effect Schema decoding, not end-to-end Worker or production latency. Record artifact size, workload, distributions and environment. A local workerd benchmark does not establish Cloudflare production latency. Keep fixtures synthetic; private HTML, source code and credentials stay outside the repository.

`bun tooling/benchmark-shell.ts <reference-runtime-directory> <current-runtime-directory> <output.json>` compares two extracted, validated runtime archives in native Alchemy workerd. It alternates eight fresh-R2 phases (ABBA then BAAB), with ten warmups and 25 samples per phase. Each request runs 64 shell reads followed by `true`, using 128 environment entries below the 64 KiB contract limit. Every sample validates the complete output. Retain every phase and raw sample; shared-host results do not establish production latency or cost.

Maintain executable contracts at their owner. `src/contracts.ts` owns the external Effect Schema API; `crates/kernel` owns serialized kernel persistence and its invariants. Alchemy resources live in `src/resources.ts` and `alchemy.run.ts`. Runtime imports from provisioning must remain type-only.

`409` conflicts require reading current state before deciding to retry. A lost response does not roll back earlier writes. Guest side effects and execution receipts do not currently form an atomic multi-object transaction; do not hide this by replaying submissions.

The current [0.10.0 local candidate evidence](docs/evidence/sdk-0.10.0-local.json) separates artifact validation from publication and remote deployment.

Before publishing SDK/runtime archives, run `bun run package:proof <sdk.tgz> <runtime.tgz>` against the exact files to upload. It checks their matching identities and licenses, consumer declarations, public exports and native binding behavior without provisioning remote resources.

`bun run minutei:proof <minutei-checkout> <runtime.tgz>` compiles the actual Minutei Code Mode/tenant fixtures against the consumer's installed SDK and runs them against the exact runtime archive through a native Agent service binding. It verifies conversation retention, authority/isolation, cleanup recovery and current filesystem/shell features without changing the consumer dependencies. The proof owns a child process with private native Alchemy registry and data directories; it requires the consumer checkout and installed dependencies, but no deployment credentials. History Queue consumption, browser authentication and model behavior are outside this gate.

Before claiming release readiness, close the completion gates in `docs/parity.md`, verify remote CI, deploy through Alchemy and prove the behavior against the authenticated remote Worker. Never publish private authentication configuration or mutate another project's infrastructure.
